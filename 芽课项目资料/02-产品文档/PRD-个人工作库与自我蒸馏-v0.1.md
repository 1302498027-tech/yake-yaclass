## 0. 一页纸

**现状**：采集端已经换代（12 个每日任务、193 格课程地图、日均 8000–10000 字），消费端还停在 9 月（旧工作台最后一份数据 2026-09-10，读的是已停更的两个旧任务）。

**三个硬数字**（2026-11-03 实测）：

| 指标 | 实测值 | 说明 |
|---|---|---|
| 已产出笔记 | 86 篇 / 8.8 万字符 | 28 篇日记 + 46 个概念 + 12 个领域 MOC + 28 份 PDF |
| 课程覆盖率 | 28 / 193 格 = **14.5%** | 「讲了几格」，不是「我能讲几格」 |
| 动手项完成率 | **0 / 78** | 28 篇日记一共 78 个勾选框，一个都没勾 |
| 个人痕迹 | **0 篇** | 86 篇里没有一句「我」的判断、复述、反驳 |
| 行为数据 | **0 行** | `data/` 下没有 `sprout.db`，四张行为表从未初始化 |

**结论**：现在这套系统在高效地**生产**，但**没有消费，也没有沉淀**。没有「我」的痕迹，就不存在可蒸馏的对象。

**做法**：不新建体系，把旧工作台的数据源换掉，加一层「证据记账」，再让工作台只干一件事——每天告诉你**今天只做这 3 件事**。

**三个必须拍板的决策**（§12）：① 复述由你手写、AI 不许代写；② 蒸馏按周跑不按天跑；③ P0 只改造不做新功能。

## 2. 问题定义

四个断层，按严重性排序。**只有第 2 个是产品能解决的**，先认这一点。

### P1 · 没有消费决策入口（最痛）

日均产出 8000–10000 字，你在 `00_使用说明.md` 里自己写过：「这个量是读不完的，别假装能读完」。现在没有东西替你决定**今天看哪一期**，于是决策成本外化成「都不看」。

### P2 · 没有反馈信号，蒸馏没有原料

28 篇日记里，`今日动手` 有 78 个勾选框，实测勾了 0 个；86 篇笔记里，「我读完了」「我不同意」「我用上了」这三类信息一条都没有。旧工作台那四张行为表（`reads/stars/answers/notes`）所在的 `data/sprout.db` 根本不存在——代码写了，从没跑起来过。

→ 系统知道 AI 讲了什么，不知道你吸收了什么。**没有原料，蒸馏只能变成 AI 替你总结 AI 写的东西**，那是自嗨。

### P3 · 进度是假的

`00_学习进度.md` 的 ✅ 是任务跑完自动打的，代表「讲过了」。它和「我能 60 秒讲清楚」之间没有任何验证。用它做求职判断会高估自己。

### P4 · 静默失败没人知道

`03_商业` 任务 status=ACTIVE、排期周二/四/六 07:40，提示词完整（3368 字）、5 个章节目录和 PDF 目录都建好了。今天就是周二，07:40 早过了，该领域 **0 格、0 篇日记**。目录建立于 11-01 06:03（周日，非排期日），今天是它第一次到点该跑。

也就是说：它今天失败了，但没有任何地方能看到——历史上有过连续 6 天断供（9/12–9/17）也没人发现。

## 3. 目标与非目标

### 3.1 目标（按优先级）

| # | 目标 | 可测定义 |
|---|---|---|
| G1 | 每天 30 秒内知道「今天只做什么」 | 打开工作台到开始读第一行，≤30 秒；今日页固定 3 张卡，不许多 |
| G2 | 让每一格都带上「我的证据」 | 4 周内 `digest` 非空的日记 ≥ 10 篇；「我的复述」中位字数 ≥ 40 |
| G3 | 蒸馏出可直接用的个人资产 | 面试弹药库 ≥ 20 条，每条含「我的原话 + 出处日记 + 追问防守」 |
| G4 | 断供 24 小时内可见 | 任一任务超期 1.5 个周期未产出 → 今日页顶部告警 |
| G5 | 能力剖面可对 JD | 能给任意一份 JD 输出「已达标 / 有证据但薄 / 空白」三档缺口 |

### 3.2 非目标（这一节是范围防火墙，逐条写清「不做什么」和「为什么」）

1. **不做编辑器**。笔记的编辑仍在 Obsidian / 本地 md 完成。工作台是**读**和**记**的地方，不复刻 Markdown 编辑、双链补全、附件管理。理由：复刻 Obsidian 是重做一个成熟的编辑器，投入产出比必然为负。
2. **不让 AI 代写「我的复述」**。这一栏留白也比 AI 代写有价值。理由：蒸馏的唯一原料是「你的原话」，代写等于污染数据源，后面所有剖面和弹药库全部失真。
3. **不接管任务调度**。12 个 automation 仍由 WorkBuddy 跑，工作台只读产物 + 读健康度。理由：调度属于平台能力，抢过来只会多一个会挂的组件。
4. **不做 12 领域全量精读的排期优化器**。v0.1 只做「今天 1 期必读」，不做长期学习计划生成。理由：排期算法在没有消费数据前调不准，属于凭空优化。
5. **不做社交与分享**。无公开主页、无排行榜、无导出分享卡。理由：个人工作库，加社交就变形。
6. **不做 PDF 在线阅读器**。第一版只给链接与下载。理由：现有 28 份 PDF 是「当天读完就过去」的阅读件，内嵌渲染器不改变阅读行为。

### 3.3 不做什么的代价（诚实写出来）

放弃「全量消化」是这份 PRD 最大的取舍：12 领域里 `商业` `国际` `健康` 三块会长期停留在 L0（讲过但没消化）。这不是 bug，是有意的资源分配——求职主线是 AI-Agent + 计算机 + 能力边界 + 需求判断 + 分析度量 + 面试。

只有一个人：你，白天实习、晚上推进、常到凌晨、开机不规律。

| 场景 | 现在 | 目标 |
|---|---|---|
| 早上 7:50 通勤前扫一眼 | 打开素材包目录，看文件名 | 打开工作台，3 张卡：今天读哪期、做什么、复习哪个概念 |

| 连续 3 天没开机 | 无感知，事后发现断了 | 今日页红条：AI-Agent 已 3 天未产出 |

## 5. 方案总览

**一句话架构**：md 是唯一事实源，SQLite 只记行为，中间加一层 `ingest` 把两者编成 `payload.json`，前端只读 payload。

```
素材包/**.md  ──┐
                ├─▶ ingest.py ──▶ payload.json ──▶ 工作台（单页 / 8848 服务）
sprout.db  ─────┘        ▲                              │
（reads/answers/         │                              ▼
  digest/notes）     行为回写 ◀───────────── 我的复述 / 勾选 / 收藏
                          │
                     每周蒸馏任务 ──▶ 14_自我蒸馏/*.md
```

### 5.1 分层职责

| 层 | 组件 | 职责 | 不做什么 |
|---|---|---|---|
| 数据层 | `素材包/**.md` | 内容 + 我的痕迹（frontmatter 字段） | 不搬进数据库 |
| 行为层 | `sprout.db` | 读了/做了/答了/收藏（带时间戳） | 不存正文 |
| 索引层 | `ingest.py` | 扫 md + 读 db → 生成 payload | 不写任何 md |
| 展示层 | 单页 HTML / `server.py:8848` | 5 个视图 | 不编辑笔记 |
| 蒸馏层 | 每周 automation | 读 L1–L3 证据 → 四份产出 | 不改日记原文 |

### 5.2 技术选型（沿用，不换栈）

- Python 3.13 + 标准库，无第三方依赖（现有 `build.py` 已是这个路子，继续用）。
- 单文件 HTML 可直接双击（现状能力，保留，断网/换机也能看）。
- 本地服务 8848 复用 `server.py`，多一个 `/api/payload` 路由。
- 上云路径不变：`YAKE_*` 环境变量 + GitHub Actions，产物是静态 HTML。

## 6. 数据层改造（最关键，其余都是它的显示层）

### 6.1 日记 frontmatter 新增 5 个字段

不改现有任何字段（避免打坏 Dataview），只在后面追加：

```yaml
read: 2026-11-04        # 我读完的日期；空 = 未读
digest: 2026-11-04      # 我写下复述的日期；空 = 未复述
level: 2                # 证据等级 0–3，见 §7.1；由系统算，不由 AI 评
applied: 1              # 落地次数（做过一次真实动手 +1）
verdict: 值得           # 值得 / 一般 / 跳过 —— 我对这篇的判断
```

### 6.2 正文新增 3 个固定区块（追加在「五、」之后、「来源」之前）

```markdown
## 我的复述
<!-- 我来写，1–3 句，不许 AI 代写；写不出就写「跳过」 -->

## 我的反驳
<!-- 我不认同的地方，或它没覆盖的场景 -->

## 我落地了什么
<!-- 做了哪个动手项、结果如何、失败了也写 -->
```

### 6.3 12 份提示词同步改一处

`素材包/{领域}/00_提示词.md` 的输出模板末尾，固定追加这三个空区块标题（**不填内容**）。

这是全套改造里唯一的侵入式改动。**已核实：12 份提示词（3322–4018 字）都只引用 `_模板/`，正文没有节标题副本**，所以只改模板一处即可，不存在改 12 遍的风险（见 §12.4）。

### 6.4 行为表扩展

```sql
-- 保留 reads / stars / answers / notes 四表不动
CREATE TABLE IF NOT EXISTS digest_log(
  date TEXT NOT NULL,          -- 日记日期
  domain TEXT NOT NULL,
  chars INTEGER NOT NULL,      -- 复述字数（用于 G2 指标）
  at TEXT NOT NULL,
  PRIMARY KEY(date,domain)
);
CREATE TABLE IF NOT EXISTS task_health(
  domain TEXT PRIMARY KEY,
  last_ok TEXT,                -- 最近一次成功产出时间
  last_grid INTEGER,
  fail_streak INTEGER DEFAULT 0
);
```

### 6.5 字段契约（ingest 的输入输出）

`payload.json` 顶层：

| 字段 | 类型 | 用途 |
|---|---|---|
| `generated` | ISO 时间 | 构建时间 |
| `progress` | 12 项数组 | 领域、已讲/总格、最后更新、健康度 |
| `entries` | 数组 | 每篇日记：date/domain/chapter/grid/grid_name/字数/勾选数/level/digest |
| `concepts` | 数组 | 47 个概念：名/领域/首见/updates/被引用次数 |
| `tasks` | 12 项数组 | 任务健康：rrule、期望间隔、最后成功、是否超期 |
| `today3` | 对象 | 今日 3 件事的计算结果（见 §8.1） |
| `ammo` | 数组 | 弹药库条目（蒸馏产出，v0.1 可为空） |

## 7. 蒸馏机制（本 PRD 的核心，也是最容易做假的一层）

### 7.1 四层证据模型

不给知识打「掌握度」自评分（自评必然虚高），只认**可留痕的行为**：

| 层 | 名称 | 判定条件（机器可判） | 权重 |
|---|---|---|---|
| L0 | 讲过 | 日记存在 | **0**（不计入能力分） |
| L1 | 复述过 | `## 我的复述` 非空且 ≥30 字 | 1 |
| L2 | 落地过 | `## 我落地了什么` 非空，或该篇动手项勾了 ≥1 | 2 |
| L3 | 用过 | 面试/工作被追问过，或复用于产出物（弹药库被引用） | 3 |

L0 权重为 0 是刻意的：**193 格全部 L0 也等于 0 分**。这样能力剖面不会因为任务跑得多而虚高——对应你「能力边界 ❌不必深入」的那套诚实标注。

### 7.2 每周蒸馏任务（1 个新 automation，周日 21:30）

**输入**：本周 `digest` 非空的日记（L1 及以上）+ 它们的 `我的复述/反驳/落地`。
**硬约束**：只允许引用本周有 L1 证据的内容；没有证据的领域直接写「本周无增量」，不许用 L0 凑数。

**产出 4 份，写进 `素材包/14_自我蒸馏/`**：

| 文件 | 内容 | 验收 |
|---|---|---|
| `能力剖面.md` | 12 领域 × 193 格的四级状态表 + 每格一句证据（指向日记名） | 每行 L1+ 的格子必须能点到出处 |
| `判断原则.md` | 从复述/反驳里抽的我的默认取舍，**同一倾向出现 ≥3 次才升级为「原则」**，每条带 3 条原文引用 | 原则 ≤10 条，每条 ≥3 引文 |
| `面试弹药库.md` | 问题 / 我的答案（原话不润色）/ 证据（哪篇哪个坑）/ 追问防守 | ≥20 条，每条 ≤60 秒可讲 |
| `缺口清单.md` | 目标 JD 关键词 vs L2 状态，三档：已达标 / 有证据但薄 / 空白 | 每档给具体条目，不给分数 |

第三份是蒸馏能不能成立的试金石：**如果弹药库里写的还是 AI 的语感，说明 L1 是空的，返工改复述，不要改弹药库。**

### 7.3 为什么按周不按天

单日只有 1–3 篇有 L1 证据，跨篇模式（同一个取舍反复出现）出不来；周粒度才有 5–15 篇，够抽「原则」。按天跑等于每天生成一份自我总结，两周后你自己也不看。

## 8. 页面与交互

### 8.1 今日页（默认首页，只放 3 件事）

**卡 1 · 今天读这一期**
选取规则（可执行，不做机器学习）：
`score = 领域权重 × 0.6 + 未消化天数归一 × 0.3 + (本章是否有 L1 证据 ? 0.1 : 0)`
领域权重：AI-Agent 1.0 / 计算机 0.9 / 能力边界 0.8 / 需求判断 0.8 / 分析度量 0.7 / 面试 0.7 / 文档表达 0.6 / 学习路径 0.5 / 财税 0.4 / 商业 0.4 / 国际 0.3 / 健康 0.3。
显示：领域 + 第几格 + 标题 + 预计阅读 6 分钟 + 一句「为什么是它」。

**卡 2 · 做这一件**
从今日所有期的「今日动手」里，挑验收成本最低的一个（有明确产出物、≤15 分钟）。显示原样的勾选标准，点一下直接落 `digest_log`。

**卡 3 · 复习这个概念**
间隔重复 1/3/7/21 天，取到期且 `updates ≥ 1` 的概念笔记，显示「一句话定义」，点开进笔记。

**顶部状态条**（两态）：
- 正常：`今日 8 期已产出 · 必读 1 期 · 待复述 1 篇`（11-02 峰值 10 期，11-03 实测 8 期）
- 异常：`⚠ AI-Agent 已 3 天未产出（应 11-01 07:00）` —— 红底，不可关闭，修好才消失。

**明确不做**：不放 12 领域全列表、不放今日全部 8–10 期标题、不放连续打卡天数。首页信息密度越低，打开率越高。

### 8.2 题库页

12 领域 → 章节 → 笔记三级树 + 全文搜索（复用现有 `palList` 命令面板）。筛选项：`level ≥1` / `未读` / `verdict = 跳过`。点开笔记在右侧抽屉读，底部三个按钮：读完 / 复述（弹输入框）/ 跳过。

### 8.3 能力剖面页

193 格热力图，12 行（领域）× 最多 18 列（格号），四色对应 L0–L3（灰/浅青/青/深青，不用红黄绿——那是评价不是账本）。点格子出抽屉：日记名、概念、我的复述、落地记录。

下方一行汇总：`已讲 28 · 复述 0 · 落地 0 · 用过 0`，四个数字并列，**不做百分比**——百分比会让人盯着分子，四个绝对数会让人盯着 0。

### 8.4 蒸馏页

四份产出的渲染 + 「本周新增」摘要；空态写实话：「本周 0 篇复述，蒸馏暂无可抽内容」。

### 8.5 运维页

## 16. P1 迭代：每日推送（2026-11-05 上线）

### 16.1 为什么推送排在功能第一位

上线一天后查数据表：**0 条记录**。页面做好了、入口也加了，但一次点击都没有。

这证明瓶颈不在功能。用户必须主动想起打开链接 —— 一个要人惦记的工具，前三天新鲜，第四天就废，9 月那版 8 视图的工作台就是前例。所以推送不是「锦上添花的提醒」，而是**决定这个产品存在与否的前置条件**。

### 16.2 一天里发现的一个真错误

11-04 白天，健康、计算机两个任务其实已经补跑成功（当天 11 个任务全部产出，日记从 28 篇涨到 39 篇）。但工作台页面仍挂着 11-03 23:56 的快照，顶部红条继续报「3 个任务该跑没跑」。

**页面是构建时快照，不是实时数据。** 这个缺陷在 P0 交付时没有被识别出来 —— 当时的数据刚好是新鲜的，所以看不出来。它会导致运维页给出**指向错误的诊断**，比没有诊断更糟。

修正方式不是加实时接口，而是让构建每天自动发生：推送任务顺带把页面重建并重新发布，把快照滞后压在 24 小时内。侧栏和页脚都保留快照时间，让滞后再长也可见。

同时修正了两处文案：
- `商业` 从「超期 1 天」改为「从未产出」（`lastOk` 为空时判定为从未跑过，而非跑过又断了）
- 运维页「怎么修」第 4 条原本指向一个已不存在的「数据」视图，改为指向 `daily_push.py`

### 16.3 做了什么

| 组件 | 路径 | 职责 |
|---|---|---|
| 正文生成 | `04-源代码/notify.py` | payload → 一封手机上能一屏读完的纯文本邮件 |
| 一条线 | `04-源代码/daily_push.py` | 扫素材包 → 重建页面 → 重新发布 → 生成正文，单步失败不中断 |
| 自动化 | WorkBuddy 每日 08:30 | 跑 `daily_push.py`，把正文发到 1302498027@qq.com |

邮件只有五段，刻意压缩到极短：

1. **1 篇** —— 领域、第几格、标题、一句话摘要、文件日期与字数
2. **今天问你一句** —— 「哪一句你觉得太理想化 / 跟做过的对不上 / 太抽象」，这是反驳的触发点
3. **顺手做 1 个** —— 只列第一条动手项，其余提示「在页面里」
4. **顺手复习** —— 一个概念 + 间隔天数
5. **断供告警** —— 区分「从未产出 / 停 N 天 / 今天没产出」三档

不放：全部 12 领域、进度百分比、统计图表。**一天只推一件该做的事。**

### 16.4 实测

- `python daily_push.py` 全链路跑通：重建 → `publishVersion` 3→5 → 生成正文，无异常项。
- 真实发送一封到 `1302498027@qq.com`（发件与收件同账号），主题「芽课 · 工具调用机制」，纯文本。
- 线上校验：静态包 77.7 KB，含 39 篇日记与「从未产出」判定，运维页 11 个任务全绿、商业标红。
- `payload` 新增 `gapDays`（距最后产出天数），比 `overdueDays`（从错过排期算起）更直观，运维页与邮件都用它。

### 16.5 仍未解决

- **推送只出不进**。邮件是单向的，回信不会写进数据表。要闭环得接邮件收件能力解析回复，成本不低，暂不做。
- **L3 `applied` 仍无入口**。「今天用了什么」还是没地方点，四层证据里第三、四层依旧空着。
- **断供只能看不能修**，运维页仍是只读。
- **08:30 这个时间没验证过**。用户活跃时段在晚间，早上是否真会看邮件，需要一周行为数据再定。

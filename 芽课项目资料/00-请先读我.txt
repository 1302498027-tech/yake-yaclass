一键部署（改完样式后执行）
  Windows：  双击 部署.cmd
  命令行：   sh 部署.sh

部署原理
  把 09-线上部署/芽课工作台-线上数据版.html 复制为 deploy/index.html，
  再用 CloudBase CLI 上传。命令带 --safe --verify：
    --safe    发布前自动备份，失败自动回滚
    --verify  上传后校验一致性
  不会带 --prune，因此不会删除线上其他文件。

CloudBase CLI 位置
  ~/.dsh-tools/cloudbase/tcb
  （自带 Node 运行时，不依赖系统 Node/npm）

首次使用需登录
  ~/.dsh-tools/cloudbase/tcb login --flow device

四、数据管线与改样式的工作流
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

数据从哪来（已修复）
  早期 build.py 扫描 WorkBuddy 的 automation-*/outputs 目录，
  但那些任务在 2026-09-19 之后已停。
  真正在跑的是 CloudBase 云函数 yake-daily：每天 21:00 用 GLM 生成
  三份日报 → 构建 → 上传静态托管，并把全部历史写进站点的
  data/manifest.json。

  现在本地管线改为「从站点同步」，与云函数同源：

    python sync_sources.py     # 从站点拉回全部日报 → outputs/{deep,learn,tech}/
    python build.py            # 解析 → 生成 index.html

  同步的代码位置：04-源代码/build.py、build_site.py
  这两个脚本已替换为 WorkBuddy/pm-learning-workbench/ 下的云端最新版
  （旧版正则已跟不上日报格式，会导致条目解析失败），并做了三处本地适配：
    1. 数据源默认指向 04-源代码/outputs/{deep,learn,journal}
    2. 打通「今日组卷」的 daily 标记（pick_daily）
    3. 技术版条目解析：支持「今日学习主题总览」列表与「核心概念：X」编号项

日常改样式
  1. 改 04-源代码/template.html
  2. cd 04-源代码 && python build.py
  3. 把 04-源代码/index.html 复制到：
       05-工作台成品/芽课工作台-双击打开.html
       09-线上部署/芽课工作台-线上数据版.html
       09-线上部署/deploy/index.html
  4. 双击根目录 部署.cmd 上线

想看最新内容（比如云端又生成了一天）
  python sync_sources.py && python build.py
